# 두툼장어 (DUTOOM EEL) 쇼핑몰

Spring Boot 3.3 · Java 21 · Thymeleaf · PostgreSQL · Flyway. 디자인 기준: `docs/reference-homepage.png`.

## 실행

```bash
docker compose up -d --build        # http://localhost:8089
```

`src/main/resources` 변경 후에는 `docker compose up -d --build app`으로 다시 빌드하고, 정적 파일은 7일 캐시되므로 브라우저에서 Ctrl+F5.

## 테스트 계정 (local 프로필)

| 구분 | 주소 | 아이디 | 비밀번호 |
|---|---|---|---|
| 관리자 | http://localhost:8089/admin | `admin@dutoom.local` | `admin1234!` |
| 회원 | http://localhost:8089/login | `kim@` `lee@` `park@` `choi@sample.local` | `sample1234!` |
| 비회원 주문조회 | http://localhost:8089/order/lookup | 주문번호 | 주문 시 입력한 비밀번호 |

샘플 회원별 데이터:

| 이메일 | 이름 | 샘플 데이터 |
|---|---|---|
| `kim@sample.local` | 김서연 | 배송 완료 주문, 후기 2건 |
| `lee@sample.local` | 이준호 | 상품 준비중 주문, 답변 완료 문의 |
| `park@sample.local` | 박지민 | 결제 대기 주문, 답변 완료 문의 |
| `choi@sample.local` | 최민수 | 배송중 선물 주문, 후기 2건 |

그 밖의 샘플: 상품 5개(패밀리팩 2kg은 품절 확인용 재고 0), 비회원 미답변 문의 1건, 브랜드 스토리 본문, 푸터 사업자 정보.
운영(local 아님)에는 샘플이 들어가지 않으며, 관리자는 `ADMIN_EMAIL`/`ADMIN_PASSWORD`가 있을 때만 생성된다.

## 주문·결제 흐름

- 주문서의 [주소 검색]은 카카오(다음) 우편번호 서비스 연동 (API 키 불필요, 실패 시 직접 입력).
- `PAYMENT_MODE=mock`(기본): PG 미연동 상태로 보고 주문 즉시 결제 완료(`PAID`, 결제수단 `TEST`) 처리 → 주문 완료 화면.
- `PAYMENT_MODE=toss`: 주문 후 결제 화면에서 토스페이먼츠 결제.

테스트 (로컬 JDK가 8이라 컨테이너에서 실행):

```bash
docker run --rm -v "$PWD:/src" -v dutoom-m2:/root/.m2 -w /src maven:3.9-eclipse-temurin-21 mvn -B test
```

## 멀티 브랜드 (식자재)

`/?brand=kimchi`처럼 브랜드 코드를 붙이면 메인의 테마 색상·문구·대표 이미지·브랜드 스토리·상품이 해당 브랜드로 바뀐다.
없는 코드나 파라미터 없음은 첫 번째(기본) 브랜드. `/products?brand=`, `/gifts?brand=`도 동일.

브랜드 추가 (예: 된장):
1. `application.yml`의 `shop.brands`에 항목 추가 (`code: doenjang`, 이름·문구·이미지·`primary`/`accent` 색상, 생략 가능 항목은 주석 참고) → 재빌드
2. 관리자 > 상품 등록에서 **브랜드**를 선택해 상품 등록 (첫 번째 일반 상품이 시그니처, "메인 시그니처" 체크 시 우선)
3. 브랜드 스토리: 관리자 > 콘텐츠에서 브랜드 스토리 추가 후, 그 주소(slug)를 `story-slug`에 지정

섹션 노출: 상품 목록 그리드 `product-grid: true`, 선물 섹션은 해당 브랜드 선물세트가 있을 때, 가이드 섹션은 `guides: true`일 때.
샘플 브랜드 `kimchi`(두툼김치)는 local 샘플 `V107`로 상품 3개·스토리 1개가 들어간다.

## 운영 배포 (.env)

```bash
cp .env.example .env    # 값 입력. compose 가 .env 의 키를 모두 앱 컨테이너에 전달
docker compose up -d --build
docker compose logs app | grep -E "사업자 정보|관리자 계정"   # 주입 확인
```

- `SPRING_PROFILES_ACTIVE=` 처럼 **비워 두면 운영 프로필**, 키 자체가 없으면 local(샘플).
- local 프로필에서 쓸 기본값(샘플 관리자·사업자 정보)을 살리려면 `.env`에서 그 줄을 지운다 (빈 값도 "설정됨"으로 본다).
- 포트는 `APP_PORT` (기본 8089). 서버 방화벽·클라우드 보안 그룹에서 해당 포트를 열어야 외부 접속 가능.
- `env_file` 의 `required: false` 는 Docker Compose 2.24 이상 필요.

## 운영 환경변수

| 변수 | 설명 |
|---|---|
| `APP_PORT` | 외부 포트 (기본 8089) |
| `SPRING_PROFILES_ACTIVE` | 운영은 비워둠 (`local`이면 샘플 상품·기본 관리자 생성) |
| `DB_URL` `DB_USER` `DB_PASSWORD` | PostgreSQL |
| `SHOP_BASE_URL` | canonical / sitemap / OG 절대 URL |
| `PAYMENT_MODE` | `mock`(테스트 결제) / `toss` |
| `TOSS_CLIENT_KEY` `TOSS_SECRET_KEY` | 토스페이먼츠 키 |
| `ADMIN_EMAIL` `ADMIN_PASSWORD` | 최초 관리자 (계정이 없을 때만 생성) |
| `COMPANY_*` | 푸터 사업자 정보 (NAME, CEO, BUSINESS_NO, MAIL_ORDER_NO, ADDRESS, PHONE, EMAIL, CS_HOURS) |
| `SHOP_SHIPPING_FEE` `SHOP_FREE_SHIPPING_OVER` | 배송비 정책 |

메인 BRAND BENEFITS / TRUST 문구는 `application.yml`의 `shop.benefits`, `shop.trust` (현재 `temp: true` 임시 문구).

## 데이터 원칙

- 스키마 변경은 Flyway 마이그레이션으로만 (`ddl-auto: validate`). DB 초기화 없음.
- `db/sample`은 local/test 프로필 전용 샘플이며 운영 DB에 들어가지 않음. 이미 적용된 파일은 수정하지 말고 새 버전(V108…)으로 추가.
- 샘플 초기화: `docker compose down -v && docker compose up -d --build` (DB 볼륨 삭제, local 전용).
- 주문 원장(금액·품목)은 관리자 화면에서도 수정 불가, 상태·송장만 변경.

## 이미지

`tools/make_assets.py`가 시안(1024×1536)에서 섹션 이미지를 잘라 `static/images`에 저장한다.
시안 해상도 한계로 데스크톱에서 1.4배 확대 표시되므로 운영 전 고해상도 원본 교체가 필요하다.


## 브랜드 스토리 추가하기

❯ 브랜드 스토리를 하나더 추가하면 어떻게 되나요?

브랜드 스토리를 하나 더 추가하면 대표 스토리(/story) 아래에 이어지는 별도 페이지가 하나 생깁니다. 메인 페이지와 대표 스토리 내용은 바뀌지 않습니다.

예를 들어 주소를 our-farm, 제목을 "우리 양식장 이야기"로 추가하면 이렇게 됩니다.

┌──────────────────────┬───────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│         위치         │                                                   변화                                                    │
├──────────────────────┼───────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ /story/our-farm      │ 새 스토리 페이지가 생깁니다. 위치 표시는 홈 › 브랜드 스토리 › 우리 양식장 이야기입니다.                   │
├──────────────────────┼───────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ /story (대표 스토리) │ 본문 아래에 「브랜드 이야기 더 보기」 카드가 나타나고, 새 스토리가 대표 이미지·제목·요약과 함께 보입니다. │
├──────────────────────┼──────────────────────────────────────────────────────────────────────────────────────────────
│ 새 스토리 페이지     │ 아래쪽에 다른 스토리 카드가 보입니다. 대표 스토리를 뺀 나머지는 노출 순서대로 나옵니다.                   │
├──────────────────────┼──────────────────────────────────────────────────────────────────────────────────────────────
│ 메인 페이지          │ 변화 없습니다. 메인의 BRAND STORY 영역은 계속 대표 스토리만 보여줍니다.                                   │
├──────────────────────┼──────────────────────────────────────────────────────────────────────────────────────────────
│ 사이트맵             │ 새 주소가 자동으로 들어가 검색엔진이 찾을 수 있습니다.                                                    │
└──────────────────────┴──────────────────────────────────────────────────────────────────────────────────────────────

추가한 스토리가 없으면 「브랜드 이야기 더 보기」 영역은 아예 나오지 않습니다. 비공개로 두면 페이지와 목록, 사이트맵에

알아두실 점
- 상단 메뉴: "브랜드 스토리" 메뉴는 계속 /story로 연결됩니다. 추가 스토리는 대표 스토리 하단 목록을 통해서만 들어갈 수 있습니다.
- 카드 이미지: 대표 이미지를 넣지 않으면 카드에 이미지 없이 제목과 요약만 나옵니다. 보기 좋게 하려면 이미지를 함께 등
